# Design Review Checklist

- [ ] Uses design tokens instead of arbitrary values
- [ ] Reuses shared components
- [ ] Clear primary action
- [ ] Reasonable information density
- [ ] Works on small mobile width
- [ ] Safe-area respected
- [ ] Keyboard does not hide critical actions
- [ ] Long labels/content do not overflow
- [ ] Loading state designed
- [ ] Empty state designed
- [ ] Error/retry state designed
- [ ] Disabled/permission state designed if relevant
- [ ] Interactive controls have adequate touch targets
- [ ] Important controls have semantic/accessibility labels
- [ ] Visual hierarchy matches surrounding screens
